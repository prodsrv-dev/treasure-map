# 03. UX Constructor

Конструктор нужно проектировать не как анкету, а как мастер сборки приключения.

Пользователь должен чувствовать: "Я делаю ребенку квест", а не "Я заполняю техническое задание".

## Главный UX-принцип

Родитель всегда должен видеть цепочку квеста:

`Письмо -> Точка 1 -> Точка 2 -> Точка 3 -> Финальный клад`

Эта цепочка должна быть постоянным боковым элементом интерфейса.

## Шаг 1. Сценарий

Пользователь выбирает:

- возраст ребенка;
- имя ребенка;
- повод: день рождения, Новый год, просто приключение, подарок от родственника;
- место проведения: квартира, двор, дача, парк, район;
- количество точек: 4, 5, 6, 8;
- стиль: пираты, лесные тайны, детектив, магия, космос;
- язык;
- тон: смешной, сказочный, торжественный, загадочный.

## Шаг 2. Точки маршрута

Главный экран конструктора.

Пользователь добавляет локации карточками:

- название места;
- 2-3 фотографии;
- короткое описание;
- что ребенок знает про это место;
- можно ли туда безопасно дойти;
- сложность загадки: легко, средне, хитро.

Пример карточки:

```text
Точка: Старая яблоня
Фото: 3 файла
Описание: дерево возле качелей, под ним часто лежит мяч
Ребенок знает: мы там часто играем летом
Сложность: легко
```

## Шаг 3. Порядок квеста

Пользователь перетаскивает точки в нужном порядке:

`Старт -> Яблоня -> Скамейка -> Песочница -> Горка -> Финальный клад`

Система объясняет механику:

- на стартовой открытке будет загадка про точку 1;
- в точке 1 будет спрятан фрагмент с изображением точки 1;
- на обороте фрагмента будет загадка про точку 2;
- последний фрагмент ведет к финальному сокровищу.

## Шаг 4. Загадки

AI генерирует несколько вариантов для каждой точки:

- стих;
- простая загадка;
- пиратское письмо;
- короткая подсказка для малышей;
- сложная подсказка для детей постарше.

Редактирующие команды:

- сделать проще;
- сделать смешнее;
- больше пиратского тона;
- короче;
- без рифмы;
- добавить имя ребенка;
- добавить подсказку для взрослых.

## Шаг 5. Образы локаций

AI превращает фото реальных мест в иллюстрации выбранного стиля.

Для каждой точки нужно показывать:

- исходное фото;
- стилизованную иллюстрацию;
- подпись;
- кнопку "сделать узнаваемее";
- кнопку "больше сказочности";
- кнопку "перегенерировать".

Важно: локация должна оставаться узнаваемой для ребенка. Нельзя превращать ее в абстрактный красивый арт.

## Шаг 6. Карта и фрагменты

Пользователь видит не Photoshop, а режимы:

- Карта;
- Фрагменты;
- Обороты;
- Подложка;
- Производство.

### Режим "Карта"

Пользователь двигает точки, маршрут, стрелки и декоративные элементы.

### Режим "Фрагменты"

Система показывает, как карта будет разрезана. Пользователь может выбрать:

- количество фрагментов;
- более простые или сложные формы;
- безопасные крупные куски для маленьких детей;
- наличие рамки/подложки.

### Режим "Обороты"

Показываются оборотные стороны фрагментов с загадками.

### Режим "Подложка"

Показывается стартовая открытка/основа с приветствием и первой загадкой.

### Режим "Производство"

Выбор:

- распечатать дома;
- заказать готовый набор;
- скачать файлы для мастерской.

## Шаг 7. Выпуск

Финальные варианты:

- PDF для домашней печати;
- PDF A4/A3 для типографии;
- SVG/DXF для лазера;
- ZIP для производственного партнера;
- готовый физический набор с доставкой.

## Минимальный MVP

Первый рабочий продукт должен уметь:

1. Принимать 4-6 точек с фото.
2. Генерировать загадки.
3. Генерировать иллюстрации локаций в одном стиле.
4. Собирать карту-подложку.
5. Разрезать карту на фрагменты.
6. Размещать лицевые и оборотные стороны в PDF.
7. Давать инструкцию родителю, где что спрятать.
