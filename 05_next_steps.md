# 05. Next Steps

## Ближайшая цель

Собрать первый сайт-конструктор, начиная с UX и минимального MVP.

## Что делать первым

### 1. Зафиксировать MVP

Первый продукт:

- не физический набор;
- не глобальная партнерская сеть;
- не полный production API;
- сначала printable/PDF-конструктор.

MVP должен принимать 4-6 локаций и отдавать PDF-квест.

### 2. Спроектировать основной интерфейс

Ключевые экраны:

1. Выбор сценария.
2. Добавление точек маршрута.
3. Сортировка маршрута.
4. Генерация загадок.
5. Генерация/выбор иллюстраций.
6. Сборка карты.
7. Проверка фрагментов и оборотов.
8. Экспорт PDF.

### 3. Сделать прототип без настоящей AI-автоматизации

Для первого интерактивного прототипа можно использовать заглушки:

- 5-6 демо-локаций;
- уже готовые изображения;
- заранее сгенерированные загадки;
- статичный пример карты;
- экспорт можно имитировать.

Цель: проверить UX конструктора.

### 4. Потом подключить генерацию загадок

Первый реальный AI-модуль:

- вход: возраст, стиль, описание точки, имя ребенка;
- выход: 3 варианта загадки;
- команды: проще, короче, смешнее, больше пиратского тона.

### 5. Потом подключить генерацию образов

Второй AI-модуль:

- вход: фото локации;
- стиль;
- описание;
- output: стилизованная, но узнаваемая иллюстрация.

### 6. Потом PDF

PDF должен включать:

- стартовую открытку;
- карту;
- лицевые стороны фрагментов;
- оборотные стороны фрагментов;
- инструкцию родителю;
- список: какую подсказку куда спрятать.

## Как должен выглядеть первый сайт

Не лендинг, а сразу рабочий инструмент.

Первый экран:

- боковая цепочка квеста;
- рабочая область конструктора;
- понятный прогресс по шагам;
- демо-проект, который можно сразу потрогать.

## Важные продуктовые решения

### Не показывать пользователю сложные слои как Photoshop

Внутри система должна иметь слои, но в интерфейсе лучше режимы:

- Карта;
- Фрагменты;
- Обороты;
- Подложка;
- Производство.

### Не продавать "AI"

Продавать нужно не AI, а готовое приключение для ребенка.

### Не начинать с партнерской сети

Партнерская сеть нужна позже. Сначала нужно доказать, что люди хотят собрать такой квест и готовы платить за PDF/preview.

## Потенциальный первый технический стек

Если делать web app:

- Next.js или Vite + React;
- Canvas/SVG-редактор для карты;
- PDF generation;
- хранение проекта в JSON;
- позже: платежи Stripe;
- позже: AI generation API;
- позже: production ZIP export.

## Следующая конкретная задача

Собрать интерактивный прототип конструктора:

- демо-данные на 5 точек;
- визуальная цепочка квеста;
- экран добавления локаций;
- экран загадок;
- экран карты/фрагментов;
- экспорт-заглушка.

Этот прототип должен стать основой для обсуждения UX и будущей разработки.
